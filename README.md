# unitree_arm — Unitree D1 arm SDK

The D1 arm is not covered by `unitree_sdk2`. Unitree ships it as a folder of
loose example programs that each recompile the generated DDS type sources.
This repo packages the same material as a proper CMake package that installs
next to `unitree_sdk2`, so a C++ project can use the Go2 and the D1 through one
consistent mechanism.

## Install

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release \
      -DCMAKE_INSTALL_PREFIX=/opt/unitree_robotics
cmake --build build -j
sudo cmake --install build          # /opt is root-owned
```

`CMAKE_INSTALL_PREFIX` is free — `/opt/unitree_robotics` just puts it beside
`unitree_sdk2` so a single prefix finds both. Installing elsewhere works; point
consumers at it with `CMAKE_PREFIX_PATH`.

Installed files, all under their own `unitree_arm/` subtree so that
reinstalling `unitree_sdk2` can never collide with them:

```
<prefix>/include/unitree_arm/idl/{ArmString_,PubServoInfo_,SetServoAngle_,SetServoDumping_}.hpp
<prefix>/include/unitree_arm/dds_wrapper/d1/{defines,d1_protocol,d1_pub,d1_sub,d1}.h
<prefix>/lib/libunitree_arm.a
<prefix>/lib/cmake/unitree_arm/{unitree_armConfig,unitree_armConfigVersion,unitree_armTargets}.cmake
```

To uninstall, delete those four paths.

## Use

```cmake
find_package(unitree_arm REQUIRED)      # pulls in unitree_sdk2 itself
target_link_libraries(my_app unitree_arm)
```

```cpp
#include <unitree_arm/dds_wrapper/d1/d1.h>
using namespace unitree::robot;

ChannelFactory::Instance()->Init(0, "eth0");

// host side: drive the arm
d1::publisher::ArmCommand cmd;
cmd.SendAllJointAngle({0, -60, 60, 0, 30, 0, 0});   // degrees, J0..J6
cmd.SendZero();

// read what it reports
d1::subscription::ServoAngle angle;
angle.wait_for_connection();
printf("J1 = %.2f deg\n", angle.angles[1]);
```

The publisher/subscription classes mirror `unitree/dds_wrapper/robots/go2`, so
`unitree::robot::d1::publisher::ArmCommand` sits alongside
`unitree::robot::go2::publisher::LowCmd` and behaves the same way.

Standing in for the arm (a simulator, a test rig) is the same API from the
other side:

```cpp
d1::subscription::ArmCommand cmd;      // decoded into cmd.command
d1::publisher::ServoAngle    angle;    // current_servo_angle, 10 Hz
d1::publisher::ArmFeedback   fb;       // rt/arm_Feedback
```

## What the layer knows

`defines.h` carries the wire constants from the developer guide: topics,
address codes, function codes, the 0..80000 stiffness range, the 10 Hz control
cycle, and `kNumServo = 7` (6 joints + 1 gripper).

`d1_protocol.h` encodes and decodes the JSON envelope
`{"seq","address","funcode","data"}` for every documented function, using
`unitree/common/json` from the SDK — no third-party JSON dependency.

Two details worth knowing, both verified against hardware documentation:

- **The gripper is one servo (J6)**, even though the CAD/URDF models it as two
  prismatic fingers. The wire value is a servo angle in degrees; converting it
  to jaw opening is a slider-crank (law of cosines) and is left to the caller.
- **Feedback topic mismatch in Unitree's own example.** The arm's driver
  publishes on `rt/arm_Feedback`, but `get_arm_joint_angle.cpp` subscribes to
  `arm_Feedback`, so its feedback handler never fires against real hardware.
  Both names are in `defines.h`; a service impersonating the arm should publish
  on both.

## Examples

`examples/` holds Unitree's six original programs, unchanged except for the
include paths and the fact that they now consume the installed package instead
of hardcoding `/opt` paths. They are the package's own smoke test — if they
build, the install is self-contained. Build them with
`-DUNITREE_ARM_BUILD_EXAMPLES=ON` (the default); binaries land in
`build/examples/`.

Each takes a network interface as its first argument and uses DDS domain 0:

```bash
./build/examples/get_arm_joint_angle lo
./build/examples/multiple_joint_angle_control lo
```

## Layout

```
include/unitree_arm/idl/          Cyclone DDS IDL types, as shipped by Unitree
include/unitree_arm/dds_wrapper/  protocol constants, codec, pub/sub facades
src/idl/                          generated CDR descriptors (must be compiled)
src/d1_protocol.cpp               codec implementation
examples/                         Unitree's original programs
```

The `.hpp`/`.cpp` pairs under `idl/` are pre-generated by Cyclone DDS's IDL
compiler. Unitree did not ship the `.idl` sources, and `idlc` is not required
to build this package.
